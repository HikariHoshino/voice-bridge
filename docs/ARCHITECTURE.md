# 架构与数据流

## 组成

声桥保持单机、少依赖的结构：

- `app.py`：Windows 桌面界面、本地 HTTP 服务、配置持久化、系统托盘和文字注入。
- `mobile.html`：由电脑端直接提供的手机页面，不依赖外部前端服务。
- `assets/`：电脑端和手机端共用的图标。
- `test_app.py`：服务接口、配置、输入格式和关键桌面行为测试。
- `VoiceBridge.spec`：PyInstaller 文件夹便携版构建配置。

## 手机到电脑

1. 手机访问带配对令牌的局域网地址。
2. 手机页面把文本以 UTF-8 JSON 发送到 `POST /send`。
3. 电脑验证令牌、接收状态、请求大小和文本类型。
4. Windows 输入层把原始文本写入 `CF_UNICODETEXT`，再向当前活动窗口发送一次 `Ctrl+V`。
5. 成功后更新累计字符数，并在手机端保留一次本地撤销记录。

该路径不会规范化换行、空格或 Markdown。发送完成后，Windows 剪贴板保留刚发送的文本。

## 电脑到手机

1. 电脑端把文字加入内存消息队列。
2. 手机页面通过 `GET /receive` 长轮询等待新消息。
3. 服务最多保留最近 50 条消息，进程退出后立即清空。
4. 手机页面把收到的原始文本插入自身文本框当前选择区或光标位置。

浏览器安全模型不允许网页直接修改其他手机 App 的光标，因此需要在声桥页面中复制后再粘贴到其他 App。

## 远程回车

手机向 `POST /enter` 发送已确认请求。电脑端通过 Windows 输入 API 对当前活动窗口发送一次回车按下和抬起事件。二级确认只在手机界面控制，是否启用由电脑配置文件保存。

## HTTP 接口

| 接口 | 方法 | 用途 |
|---|---|---|
| `/` | GET | 返回手机页面 |
| `/send` | POST | 手机文字发送到电脑当前光标 |
| `/enter` | POST | 在电脑当前窗口按下回车 |
| `/receive` | GET | 手机长轮询接收电脑文字 |
| `/settings` | GET/POST | 读取或修改手机端确认设置 |

所有接口都要求查询参数中的配对令牌。单次手机文本请求上限为 100 KB。

## 线程模型

- Tk 主线程只处理窗口和控件。
- 初始化在线程中完成，避免网卡探测和服务绑定阻塞启动界面。
- `ThreadingHTTPServer` 为手机请求创建工作线程。
- 电脑到手机使用最长约 20 秒的条件变量长轮询。
- 托盘动作通过线程安全队列交回 Tk 主线程。

## 持久化

配置位于 `%LOCALAPPDATA%\VoiceBridge\config.json`，包含：

- 随机配对令牌；
- 主题、关闭行为和发送快捷键；
- 手机端二级确认选项；
- 功能显示选项和累计字符数。

传输正文不写入磁盘。详细威胁边界见 [SECURITY.md](../SECURITY.md)。
